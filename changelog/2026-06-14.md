## Day 15 — M3.5: Graceful Shutdown
**MR:** [feat(day-15): graceful shutdown — SIGTERM handler + drain timeout on all services](https://github.com/kekcoke/kendo/pull/19) · merged `19eb0f1`

### Changed
- **Shared:** New `src/Shared/GracefulShutdown/` module — `RequestTracker` (thread-safe in-flight counter), `GracefulShutdownMiddleware` (returns 503 RFC 7807 during drain, health endpoints bypassed), `GracefulShutdownHostedService` (triggers drain on SIGTERM via `StopAsync()`, waits for completion), `GracefulShutdownServiceCollectionExtensions` (`AddKendoGracefulShutdown()` with configurable timeout via `GracefulShutdown__TimeoutSeconds`, default 30s)
- **Gateway, UserService, Worker:** Each wired with `AddKendoGracefulShutdown()` + `app.UseMiddleware<GracefulShutdownMiddleware>()` in the middleware pipeline
- **Drain flow:** SIGTERM → `GracefulShutdownHostedService.StopAsync()` → `RequestTracker.StartDraining()` → middleware rejects new requests (503) → `WaitForDrain(timeout)` blocks until in-flight requests complete or timeout expires → process exits
- **Tests:** 13 new unit tests (7 RequestTracker + 6 middleware) covering drain blocking, timeout expiry, health bypass, concurrent request tracking, correct RFC 7807 503 body
- **Ops:** `ops/runbooks/day_15_runbook.md` — drain architecture diagram, Docker integration notes, failure scenarios, rollback plan

### Deferred
- M3.6 — Ops Runbooks: documented recovery playbook for each failure scenario
- **Carry-forward:** `chaos-test` CI flakiness — `test_db_downtime` intermittently fails returning 000000 instead of 503; pre-existing, unrelated to Day 15 changes

### Fixed
- None

## Day 14 — M3.4: Rate Limiting & Load Shedding
**MR:** [feat(day-14): M3.4 Rate limiting & load shedding](https://github.com/kekcoke/kendo/pull/17) · merged `7ebef5b`

### Changed
- **Shared:** New `src/Shared/RateLimiting/` module — `RateLimitingOptions`, `RateLimitingServiceCollectionExtensions` (registers `FixedWindowRateLimiter` + `ConcurrencyLimiter` singletons), `RateLimitingMiddleware` (fixed-window, 429 + Retry-After), `LoadSheddingMiddleware` (concurrency limiter, 503 RFC 7807), `RateLimitingApplicationBuilderExtensions` (`UseKendoRateLimiter()`, `UseKendoLoadShedding()`)
- **Gateway:** Wired `AddKendoRateLimiting()`, `UseKendoLoadShedding()`, `UseKendoRateLimiter()` into middleware pipeline; added `RateLimiting` config section to `appsettings.json`
- **Middleware order:** `LoadSheddingMiddleware` → `RateLimitingMiddleware` → `ProblemDetailsMiddleware` → Controllers
- **Health bypass:** Both middleware bypass `/health/live` and `/health/ready` to prevent health-check cascade failures
- **Tests:** 8 new unit tests (4 rate limiter + 4 load shedding) covering 429/503, health bypass, Retry-After header, RFC 7807 content type
