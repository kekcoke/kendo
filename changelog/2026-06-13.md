## Day 05 — M1.5: RFC 7807 Problem Details
**MR:** [feat(day-05): RFC 7807 Problem Details middleware across all services](https://github.com/kekcoke/kendo/pull/6) · merged `26ab7cd`

### Changed
- New `KendoProblemDetails` DTO + `ProblemDetailsMiddleware` in `Kendo.Shared.ErrorHandling` namespace — catches all unhandled exceptions and returns standardized RFC 7807 `application/problem+json` responses
- Exception→status mapping: `ArgumentException`→400, `KeyNotFoundException`→404, `OperationCanceledException`→503, generic→500, client-disconnect→499
- OpenTelemetry `traceId` auto-populated in every error response for end-to-end correlation
- Health endpoints (`/health/live`, `/health/ready`) explicitly exempted — remain `text/plain`
- Middleware wired into Gateway, UserService, and Worker `Program.cs` via one-liner `UseKendoErrorHandling()`
- Consistent JSON serialization config (camelCase, enums as strings) applied to all 3 services
- `SuppressModelStateInvalidFilter` set for unified validation error handling through middleware
- 10 new unit tests covering health skip, 400/404/499/500/503 exceptions, trace-ID, and content-type
- Dockerfiles restructured to use repo root build context — fixes pre-existing shared project reference issue
- Full test suite: 39/39 passing (29 existing + 10 new ProblemDetails middleware)

### Deferred
- None

### Fixed
- Dockerfile build context changed from per-service directories to repo root (`./src`) — enables `Kendo.Shared` project reference resolution in Docker builds (carried over from Day 01–04)
- Carry-forward from Day 00: "Define global RFC 7807 error schema" — resolved and closed
