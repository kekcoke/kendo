## Deployment

The `eval-gate` CI job in `.github/workflows/ci.yml` runs automatically on every PR touching `src/FastAPIService/` or `tests/fastapi/eval/`. No manual deployment needed — this is CI infrastructure only.

- **Eval datasets:** `tests/fastapi/eval/datasets/` — starts empty, one JSON file per workload
- **Baselines:** `tests/fastapi/eval/baseline/` — auto-generated by `regenerate_baseline.py`

## Verification

### Pre-merge

| Check | Command | Expected |
|-------|---------|----------|
| Eval suite with empty dataset | `pytest tests/fastapi/eval/ -v` | All tests skip — exit 0 |
| Existing tests | `pytest tests/fastapi/ tests/resilience/` | All pass — exit 0 |
| CI file valid | `python -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))"` | No errors |

### Post-merge

- Confirm `eval-gate` job runs on next PR
- Confirm empty dataset = skipped tests = green CI
- Confirm `eval-report.xml` artifact appears

## Adding a Workload Dataset

1. Create JSON file in `datasets/`:
```json
[
  {
    "input": "Event description text",
    "actual_output": "{ structured event JSON }",
    "expected_output": "{ golden event JSON }",
    "retrieval_context": ["Past event context"]
  }
]
```

2. Regenerate baselines:
```bash
cd src/FastAPIService
python -m tests.fastapi.eval.regenerate_baseline
```

3. Commit dataset + baseline together.

## Regenerating Baselines

```bash
cd src/FastAPIService
python -m tests.fastapi.eval.regenerate_baseline
git add tests/fastapi/eval/baseline/
git commit -m "chore(eval): regenerate baselines after [reason]"
```
