## Data Contracts

### PostgreSQL — Database Schema (Initial Migration)

**Database:** `kendo_users`  
**Extension:** `pgvector` (enabled in migration)  

No entity tables yet — M1.2 establishes the connectivity and extension, not the domain model. The initial migration:
1. Creates the `kendo_users` database (or EF Core creates it via connection string).
2. Enables the `vector` extension: `CREATE EXTENSION IF NOT EXISTS vector;`

### Connection String

```json
// appsettings.json — placeholder; overridden by env var
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=kendo_users;Username=kendo;Password=kendo_dev"
  }
}
```

**Environment variable override (Docker Compose):**
```yaml
ConnectionStrings__DefaultConnection: "Host=postgres;Port=5432;Database=kendo_users;Username=kendo;Password=kendo_dev"
```

### EF Core DbContext

```csharp
namespace Kendo.UserService.Data;

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.HasPostgresExtension("vector");
    }
}
```

**No entity DbSets** in M1.2 — the extension is enabled at the model level. Entity tables arrive in subsequent milestones when domain models are defined.

## Open Questions / Clarifications

- **pgvector image:** Recommend `pgvector/pgvector:pg16` (official pgvector Docker image) — lighter than installing the extension manually. Confirm if any enterprise policy requires the base `postgres:16` image instead.
- **Database credentials:** Using `kendo` / `kendo_dev` for local development. `.env` file pattern from Day 01 will be extended. Confirm these defaults are acceptable.
- **No entity tables yet:** M1.2 intentionally creates only the extension — no `Users` table. Domain entities arrive when the roadmap requires them (likely M1.3 or a future user-story milestone). This keeps M1.2 minimal and verifiable.
