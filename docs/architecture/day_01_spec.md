## Data Contracts

### Health Check Contracts (shared across all services)

**`GET /health/live`** — Liveness probe

```
Response 200 OK:
Content-Type: text/plain

Healthy
```

**`GET /health/ready`** — Readiness probe

```
Response 200 OK:
Content-Type: text/plain

Ready
```

> **Note:** Both endpoints return simple text for M1.1. They will be upgraded to structured JSON with dependency status in M1.6. No data models or request bodies are required.

### Port Assignments

| Service | HTTP Port | Health Port |
|---------|-----------|-------------|
| Gateway | 5000 | 5000 |
| UserService | 5001 | 5001 |
| Worker | 5002 | 5002 |

## Configuration Strategy

- **Environment variables** for all runtime settings (ports, URLs) — no hardcoded values.
- `appsettings.json` contains only defaults; overridden by `ASPNETCORE_URLS` and `DOTNET_ENVIRONMENT` at runtime.
- Docker Compose injects port mappings and health check commands via `environment:` blocks.
- `.env.example` committed to repo; `.env` in `.gitignore` (already configured).

**Required environment variables per service:**

| Variable | Gateway | UserService | Worker |
|----------|---------|-------------|--------|
| `ASPNETCORE_URLS` | `http://+:5000` | `http://+:5001` | `http://+:5002` |
| `DOTNET_ENVIRONMENT` | `Development` | `Development` | `Development` |

## Open Questions

1. **Docker Compose — existing or new?** The Day 00 scaffolding mentions "Docker Compose configured" with Postgres, RabbitMQ, Redis already defined. Should M1.1 extend that existing compose file or produce a separate `docker-compose.yml` for the application services? *Resolved: produce a root `docker-compose.yml` for app services; the Day 00 infrastructure compose file is presumed at `ops/docker-compose.infrastructure.yml` or similar.*

2. **Worker health check mechanism:** .NET Worker Service templates don't include HTTP by default. The spec proposes adding `Microsoft.AspNetCore` middleware on a separate port for health checks. Confirm this is acceptable, or prefer a sidecar approach. *Resolved: use embedded Kestrel on the worker for health checks — simplest approach, no sidecar needed.*
