# Day 01 — .NET 10 Solution Scaffold & Multi-Service Foundation

## Lesson Context
**Curriculum position:** Week 1, Day 1 — Foundation  
**Phase plan:** 01 (Core APIs & Synchronous Resilience)  
**Estimated effort:** 6–8 hours  
**Target environment:** Docker Compose with hot-reloading enabled

---

## Background

You are initializing the platform that will be built over the next 180 days. Today's goal is purely structural: get a working .NET 10 solution with two independently runnable services, both containerized and wired to a shared PostgreSQL database with the pgvector extension enabled.

No business logic today. No authentication. No resilience policies yet. Those come in subsequent days. Today's job is to lay a foundation that every future day can build on — and to prove it works before you build anything on top of it.

---

## Deliverables

### 1. Solution Structure
Create a `src/` directory containing a .NET 10 solution (`Infraspekt.sln`) with the following projects:

| Project | Type | Purpose |
|---|---|---|
| `Infraspekt.Api` | ASP.NET Core MVC (Controllers) | Gateway — public-facing REST API |
| `Infraspekt.UserService` | ASP.NET Core MVC (Controllers) | User domain — data + business logic |
| `Infraspekt.Worker` | .NET Worker Service | Background task processor |
| `Infraspekt.Data` | Class Library | EF Core DbContext, entities, migrations |
| `Infraspekt.Tests` | xUnit test project | Unit + integration tests |

**Constraints:**
- All projects target `.NET 10`.
- No Minimal APIs. MVC Controllers only (`[ApiController]`, `[Route]` attributes).
- No business logic in `Infraspekt.Api` — it is a thin gateway only today.
- `Infraspekt.Data` is referenced by `Infraspekt.UserService` and `Infraspekt.Worker`. `Infraspekt.Api` does NOT reference `Infraspekt.Data` directly.

### 2. Database Layer
- `Infraspekt.Data` must contain an `AppDbContext` (EF Core 10) with:
  - `OnModelCreating` calling `Database.EnsureCreated()` pattern replaced by migrations.
  - `pgvector` extension enabled via a raw SQL migration: `CREATE EXTENSION IF NOT EXISTS vector;`
  - A single seed entity: `HealthRecord` (`Id` guid PK, `Status` string, `CreatedAt` DateTimeOffset, `Embedding` Vector(1536)).
- Connection string loaded from environment variable `DATABASE_URL`. No hardcoded strings.
- Initial EF Core migration named `InitialCreate` applied on startup (use `MigrateAsync()` in `Program.cs`).

### 3. Health Check Endpoints
Each service that exposes HTTP must register and map:
- `GET /health/live` → liveness (always returns 200 if process is up)
- `GET /health/ready` → readiness (checks DB connectivity)

Use `Microsoft.Extensions.Diagnostics.HealthChecks`. Wire the EF Core health check for readiness.

### 4. Docker Compose
`docker-compose.yml` at repo root must define:
- `db` — `pgvector/pgvector:pg16` image, port `5432`, named volume `pgdata`, env vars for user/password/db.
- `api` — built from `ops/Dockerfile.api`, port `8080`, depends on `db` with `condition: service_healthy`.
- `userservice` — built from `ops/Dockerfile.userservice`, port `8081`, depends on `db` with `condition: service_healthy`.
- `worker` — built from `ops/Dockerfile.worker`, depends on `db` with `condition: service_healthy`.
- All services receive `DATABASE_URL` from a `.env` file (provide `.env.example`).
- `db` service must have a `healthcheck` using `pg_isready`.

### 5. Smoke Test
One xUnit test in `Infraspekt.Tests` using `WebApplicationFactory<Program>`:
- `GET /health/live` on `Infraspekt.Api` returns `200 OK`.
- `GET /health/ready` on `Infraspekt.Api` returns `200 OK` when DB is reachable.

The test must use `Testcontainers.PostgreSql` to spin up a real pgvector container — no mocking of the DB layer.

## Success Criteria
- [ ] `docker compose up` starts all four services with zero errors.
- [ ] `db` health check passes; all services reach `healthy` state within 30s.
- [ ] `GET http://localhost:8080/health/live` → `200 OK`
- [ ] `GET http://localhost:8080/health/ready` → `200 OK`
- [ ] `GET http://localhost:8081/health/live` → `200 OK`
- [ ] `GET http://localhost:8081/health/ready` → `200 OK`
- [ ] `dotnet test` passes — smoke tests green against Testcontainers.
- [ ] EF Core migration `InitialCreate` applied; `HealthRecord` table and `vector` extension present in DB.
- [ ] No connection strings hardcoded; all config via environment variables.
- [ ] `.env.example` committed; `.env` in `.gitignore`.
